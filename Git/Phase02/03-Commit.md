# 📸 Commit

## What is a Commit?

A **Commit** is a saved snapshot of your project at a specific point in time.

When you commit, Git permanently records the changes that are currently in the **Staging Area** and stores them in the **Local Repository**.

Think of a commit as **saving a checkpoint** in your project that you can return to later if needed.

---

# What is a Snapshot?

A **Snapshot** is the state of your project at the moment you create a commit.

Instead of saving only the changed file, Git stores a snapshot of your project. If a file hasn't changed since the previous commit, Git efficiently references the existing version instead of storing it again.

### Example

Suppose your project contains:

```text
MyProject/
│
├── index.html
├── style.css
└── app.js
```

### Commit 1

```text
index.html
style.css
app.js
```

You modify only `app.js`.

### Commit 2

```text
index.html
style.css
app.js (Updated)
```

Git records this as a new snapshot of your project.

---

# What is a Commit Hash?

Every commit has a unique identifier called a **Commit Hash**.

A commit hash is a long hexadecimal string generated by Git.

### Example

```text
9fceb02d0ae598e95dc970b74767f19372d61af8
```

Usually, only the first few characters are displayed:

```text
9fceb02
```

### Purpose

The commit hash allows Git to:

* Uniquely identify each commit.
* Restore a previous version.
* Compare commits.
* Track project history.

No two commits have the same hash.

---

# What is a Commit Message?

A **Commit Message** is a short description explaining what changes were made in the commit.

It helps you and your team understand the purpose of each commit.

### Example

```text
Added login page
```

```text
Fixed payment calculation bug
```

```text
Updated README documentation
```

---

# Create a Commit

Use the following command:

```bash
git commit -m "Added Login Page"
```

### Breakdown

* `git commit` → Creates a new commit.
* `-m` → Specifies the commit message.
* `"Added Login Page"` → Describes the changes.

---

# Commit Workflow

```text
Working Directory
        │
        ▼
 Staging Area
        │
git commit -m "Message"
        │
        ▼
 Local Repository
```

---

# Good Commit Messages

A good commit message should:

* Clearly describe the change.
* Be short and meaningful.
* Focus on one task.
* Use simple language.

### Good Examples

```text
Added user authentication
```

```text
Fixed login validation bug
```

```text
Updated API documentation
```

```text
Refactored Account trigger
```

```text
Added unit tests for OrderService
```

---

### Poor Examples

```text
Changes
```

```text
Update
```

```text
Fixed stuff
```

```text
Work
```

These messages do not explain what actually changed.

---

# Atomic Commits

An **Atomic Commit** is a commit that contains **one logical change**.

Each commit should focus on a single feature, bug fix, or improvement.

### Good Example

Commit 1

```text
Added login page
```

Commit 2

```text
Fixed login validation
```

Commit 3

```text
Updated login page styling
```

Each commit has a single purpose.

---

### Poor Example

One commit containing:

* Login page
* Payment module
* Dashboard changes
* Documentation update
* CSS fixes

Commit message:

```text
Updated project
```

This makes it difficult to understand or revert specific changes.

---

# Why Atomic Commits Are Important

Atomic commits make it easier to:

* Understand project history.
* Review code changes.
* Find bugs.
* Revert a specific change without affecting unrelated work.
* Collaborate with team members.

---

# Best Practices

* Commit frequently.
* Keep commits small and focused.
* Write meaningful commit messages.
* Commit only completed work.
* Stage only the files related to the current task before committing.

# Summary

| Term               | Description                                                      |
| ------------------ | ---------------------------------------------------------------- |
| **Commit**         | A saved snapshot of your project stored in the local repository. |
| **Snapshot**       | The state of your project at the time of the commit.             |
| **Commit Hash**    | A unique identifier assigned to every commit.                    |
| **Commit Message** | A short description explaining what the commit contains.         |
| **Atomic Commit**  | A commit that contains one logical, focused change.              |

---

# Key Points

* A **commit** permanently saves the staged changes in the Local Repository.
* Every commit represents a **snapshot** of your project.
* Each commit has a unique **commit hash** for identification.
* A clear **commit message** makes project history easy to understand.
* Prefer **atomic commits** by committing one logical change at a time.
* Small, focused commits are easier to review, test, and revert.
